# 内容拆解工具

> **teardown**（拆解）· 用 12 项指标拆解为什么爆/为什么不爆

拆解的目标不是评价好坏，是**找出可复用的结构**和**可量化的偏离**。

**所有判断都要能回到数字。** 感觉不算结论。

---

## 第一步：先算指标

**必须先用脚本算，不能凭读感。**

```bash
python3 scripts/analyze.py <你的文章.md>
```

脚本会加载 `references/dist.json`（899 篇的单篇指标分布），输出每个指标的**百分位定位**。

**没有 python 就手工数，但一定要数**，不能跳过。

### 12 个指标

| 指标 | 含义 |
|---|---|
| 字数 | 总量 |
| 段落数 | 分段密度 |
| 段落中位长度 | **最重要的指标之一**，决定手机端可读性 |
| ≤15字段落占比 | 竖屏字幕适配度 |
| ≤30字段落占比 | 手机阅读舒适度 |
| 问句段落占比 | 节奏变化 |
| 对话段落占比 | 叙事感 |
| 数字分段数 | 是否用了 01/02/03 骨架 |
| 脏话密度/万字 | 语域强度 |
| 第二人称密度/万字 | 读者代入度 |
| 第一人称密度/万字 | 作者在场感 |
| 标题长度 | 平台适配度 |

### 基线（899 篇实测中位）

```
字数 2,423 · 段落数 88 · 段落中位 22 字
≤15字占比 0.29 · ≤30字占比 0.70
第二人称 82.15/万字 · 第一人称 173.50/万字
标题长度 16 字
```

---

## 第二步：跟基线比

**用百分位判断，不要用「高于中位」判断。**

### ⚠️ 最重要的一条纪律：偏离 ≠ 缺陷

**基线是"她的写法分布"，不是"标准答案"。**

脚本输出每个指标在 899 篇中的**百分位**。解读规则：

| 百分位 | 含义 | 该不该动手 |
|---|---|---|
| p90 以上 | 极端值（只有 10% 的文章这么写） | ✅ 值得看 |
| p75–p90 | 特征突出（25% 的文章这样） | ⚠️ **通常不动**——这是风格，不是毛病 |
| p25–p75 | 常见区间 | ❌ 不动 |
| p10–p25 | 偏另一端 | ⚠️ 视情况 |
| p10 以下 | 极端值 | ✅ 值得看 |

**这是真实发生过的事故**：我最初把「高于 p75」直接标成「要改」。
测试时用真实爆文跑，段落中位 25.5 字（第 78 百分位）被判「段落偏厚，建议拆段」——
**这是错的。** p75 的定义就是"有 25% 的文章高于它"，把 25% 的正常写法叫缺陷，
等于让用户改掉自己的风格。

### 只在三种情况给修改动作

1. **p90 以上 / p10 以下的极端值**
2. **平台硬约束**（如标题 >20 字发不了小红书）
3. **结构性缺失**（没有心理位置、没有缺口感开头、结尾不能截图）

### 体裁识别

**清单型文章（含 ≥3 个编号段）不参与段落长度类诊断。**
它的每个条目是「编号+小标题+解释」，段落天然长。
实测：某清单文段落中位 73 字，是全库 p100——但那是**正常现象**。

---

## 第三步：结构层拆解

数字之外，看四个结构问题：

### 1. 心理位置是否明确？

读完前 3 段，能不能说出**读者被安排成了谁**？

八种位置：被辜负的人 / 终于清醒的人 / 忍无可忍的人 / 被世界亏欠的人 /
比别人更早看透的人 / 正在错过机会的人 / 有资格审判别人的人 / 被作者独家理解的人。

**说不出来 = 结构问题。**

### 2. 前 3 秒有没有缺口感？

实测开头形态分布：短断言 **37.0%** / 题记式 29.8% / 设问 13.2% / 故事起手 2.1%

⚠️ 题记式从 2015 年的 92.7% 降到 2018 年的 4.3%——**现代写法不建议用**。

### 3. 中段有没有"一个人 → 一代人"的扩大？

没有扩大 = 只是个故事，没有转发理由。

### 4. 结尾能不能单独截图？

结尾金句要能脱离全文使用。**不能截图 = 没有转发理由。**

## 第四步：输出诊断

```markdown
## 一句话诊断
（最核心的问题或优势）

## 指标对比
| 指标 | 本文 | 基线中位 | 百分位 | 判断 |
|---|---|---|---|---|

## 结构诊断
### ✅ 做对的
- （带原文引用）
### ⚠️ 偏离的
- （带数字）

## 最小修改动作
1. （具体到改哪一段、改成什么）
2. ...
```

**要求**：每个问题必须给出**具体位置 + 最小修改动作**。
**禁止**说「感觉不够抓人」「情绪不够强」这类无法验证的话。

---

## 第五步：对比拆解（可选）

如果用户给了两篇（自己的 + 对标的），做逐指标对比：

```
指标            你的        对标        差距
段落中位长度     45         21         -53%
第一人称密度     40         180        -78%
标题长度         28         16         -43%
```

**然后回答一个具体问题**：差距最大的是哪一项，它对结果的影响是什么。

---

## 一条硬纪律：不要编造诊断理由

**遇到你无法解释的极端值，直接说「这项我不知道原因」。**

**这是真实发生过的事故**：第一次跑一篇清单型文章时，Skill 遇到「段落中位长度第 100 百分位」这个它无法解释的值，于是输出了：

> 先修数据，再谈改稿。用句末标点重切后再跑一次脚本——在污染数据上做的任何「拆段」建议都是错的。

**但数据没有污染。** 核对过：原文和导出文件都是 63 段、中位 73 字，完全一致。
真实原因是清单型体裁，不是数据问题。

**LLM 面对异常数据的默认行为是编一个合理解释，而不是说"不知道"。**
这在诊断类任务里是致命的——用户会照着错误理由去改稿。

所以：
- 无法解释的极端值 → 说「这项我不确定原因，建议人工看一眼」
- 不要推测「文件格式问题」「编码问题」「数据被污染」这类技术理由，除非你**验证过**
- 基线数据来自 899 篇全量，是可信的；**异常值更可能是体裁或风格差异，不是数据错误**

## 常见诊断结论（附依据）

| 症状 | 指标特征 | 依据 |
|---|---|---|
| 「读起来累」 | 段落中位长度 >30（p90 以上） | 源语料单篇 p90 = 29 字 |
| 「没有代入感」 | 第二人称密度 <50 | 源语料中位 82.15 |
| 「像资料汇编」 | 第一人称密度 <100 | 源语料中位 173.50 |
| 「没有转发理由」 | 结尾不能单独截图 | 源语料 GLD 库 2,978 条，单篇中位 3–4 个金句 |
| 「开头留不住人」 | 开头是背景铺垫或自我介绍 | 源语料钩子 967 条 |
| 「小红书发不出去」 | 标题 >20 字 | 平台硬限制 |

---

## 边界

拆解不用于：判断内容是否真实（那是事实核查）/ 预测具体流量数字（无法预测）/ 评价作者人品。

**只拆结构，不拆人。**

**引用纪律**：可以引用 `references/` 里的数据。不要凭记忆编造"原作者说过"。
