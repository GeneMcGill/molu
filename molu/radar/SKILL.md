# 热点雷达

> **radar**（雷达）· 抓实时热点，过滤红线，转成可写选题

**解决的问题**：本地语料停在 2018-12。写法不会过时（实测四年不变），但**话题会**。

这个模块只做一件事：**把当下的热点，接上已有的写法资产。**

---

## 架构：雷达是入口，不是终点

```
互联网实时数据
      ↓
  radar（本模块）  ← 抓取 + 去重 + 红线过滤 + 主题映射
      ↓
  topic / reuse / writer / video
```

**雷达不写正文。** 抓到热点后交给下游模块。

---

## 第一步：抓取

```bash
python3 fetch.py hot              # 全网热榜（推荐，无需登录）
python3 fetch.py hot --limit 30
python3 fetch.py topic "关键词"    # 主题检索（可能需要登录态）
python3 fetch.py check            # 数据源健康检查
```

### 数据源实况（实测）

| 功能 | 状态 |
|---|---|
| **全网热榜**（微博/百度/抖音/头条/B站/知乎） | ✅ **完全可用，无需登录** |
| 主题检索 | ⚠️ 部分可用（微信公众号 + 百度可用；其余需登录态） |

**热榜可用就够了**——它是「跟上节奏」最稳定的入口。

---

## 第二步：三道自动处理

### 1. 去重

跨平台同一事件合并。实测：98 条原始 → 82 条去重。
跨平台同时在榜的会被标 🔥（真实热度，不是单平台刷的）。

### 2. 红线过滤（12 类，命中即排除）

| 类别 | 触发词示例 |
|---|---|
| 真实悲剧/伤亡 | 死亡 / 遇难 / 事故 / 火灾 / 自杀 |
| 司法案件 | 案 / 宣判 / 获刑 / 起诉 / 警方通报 |
| 时政/官方 | 新闻联播 / 国务院 / 政府 / 党建 |
| 军事/国防 | 解放军 / 国防部 / 导弹 / 军演 |
| 外交/国际 | 外交部 / 制裁 / 领土 / 主权 |
| 宏观经济/政策 | GDP / 央行 / 社保 / 养老金 |
| 医疗/疾病 | 癌 / 中毒 / 疫情 / 患者 |
| 灾害 | 地震 / 洪水 / 台风 / 爆炸 |
| 未成年受害 | 幼儿 / 儿童 / 幼儿园 |
| 性别对立 | 女拳 / 男拳 / 田园女权 |
| 体育赛事 | KPL / 世界杯 / 冠军 / 联赛 |
| 娱乐八卦 | 开播 / 定档 / 塌房 |

**实测过滤率 33%**（98 → 82 去重 → 55 可写）。
**这个比例是正常的**——热榜是新闻驱动，不是选题驱动。

### 3. 主题映射

映射到 12 类主题，供下游调用老语料：

```
存款利率普遍上调了
    主题：金钱观 · 百度热搜#3、微博热搜#4
    ↳ 老语料可调用靶子 77 条
```

**这个「↳」是关键**——它说明这条热点能接上语料里的靶子/金句。

---

## 第三步：人工过一遍

脚本输出的是**候选池**，不是成品。你要判断：

| 判断 | 通过 | 淘汰 |
|---|---|---|
| **有痛感吗** | 读者能投射自己的经历 | 纯资讯 |
| **有争议吗** | 会有人反对 | 谁都同意 |
| **能接老语料吗** | 有「↳ 可调用靶子 N 条」 | 映射不到主题 |
| **时效够吗** | 热点生命力 1-2 天 | 已经过气 |

**实测**：55 条可写热点里，真正值得写的通常只有 **3-8 条**。

---

## 关键纪律：热点只是「由头」

```
❌ 写热点本身："存款利率上调了，大家要注意"
✅ 用热点做入口："利率涨了 0.1%，你的存款还是救不了你" → 永恒痛点
```

**判断标准**：把热点换成同类事件，这篇还成立吗？

- 成立 → 你写的是**方法/处境** ✅
- 不成立 → 你写的是**新闻**，那不需要这套 Skill ❌

### 真实案例（实测）

热点：某科技大佬展示原型机后，某加密交易所追踪合约 1 小时成交量 +1580%

```
❌ 新闻写法：《Hyperliquid 成交量暴涨 1580%，注意关注》
✅ 由头写法：《不需要开户，才是它最危险的地方》
             —— 靶子：门槛越低越好 = 方便、公平
             —— 切入：便利是放大器，不是保护层
             —— 换成 NFT / 零首付 / 一键抄袭 AI 都成立
```

---

## 第四步：交给下游

```bash
# 只要选题
用 topic 模块，输入热点标题 + 领域 + 读者

# 要复用角度
用 reuse 模块，主题=热点标题

# 直接写
用 writer 模块，选题=热点衍生的题目

# 一条龙
"用 radar 抓热榜 → 挑 3 条最值得写的 → 用 topic 各出 10 个选题"
```

```markdown
- 主题：{主题}

### 已排除（红线）
（列出被过滤的，说明为什么）
```

## 其他纪律

### 1. 绝不编造热点细节

```
❌ "我朋友昨天因为存款利率调整亏了 20 万"（编的）
✅ "利率上调这件事，让很多人第一次意识到……"（不编具体人）
```

**这是硬红线。** 2019 年某头部账号因合成案例被永久封禁。

### 2. 红线内容一律不碰

脚本已过滤。如果用户手动指定了红线题材（如某个悲剧事件），**要拒绝**：

> 这个题材涉及真实伤亡，不能做情绪化加工。我可以帮你想一个同类但不涉及真实事件的切入点。

### 3. 时效诚实

热点生命力通常 1-2 天。如果抓到的数据是几天前的，要说明。

---

## 局限（必须说清楚）

1. **主题检索能力受限**——未登录时只有微信公众号 + 百度可用
2. **热榜 ≠ 选题**——33% 是红线内容，剩余大部分是资讯
3. **无法验证预测**——不能预测哪条会爆，只能判断「有没有痛感」
4. **语料时差**——老语料停在 2018-12，写法可用，**具体案例不能直接搬**
5. **依赖外部工具**——`last30days-cn` 缺失时脚本明确报错，不静默失败
