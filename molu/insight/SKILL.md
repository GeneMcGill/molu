# 洞察研究

> **insight**（洞察）· 读者是谁、卡在哪、未被满足的需求

**这是管道的第一个环节，也是决定内容上限的环节。**

对应职能：4A 的 **Account Planning**、咨询的 **Consumer Insight**、媒体的 **Audience Research**。

---

## 核心区分：观察 ≠ 洞察

```
观察：25-35 岁女性在一线城市工作，月薪 1-2 万
洞察：她们最怕的不是穷，是"我已经很努力了，但还是没跑赢同龄人"
```

**观察是事实，洞察是事实背后的张力。**

一个合格的洞察必须能回答：**为什么读者会有这个行为？**

---

## 第一步：四层拆解

### 层 1：人口统计（最不重要，但必须先排除）

```
年龄 / 性别 / 城市 / 收入 / 职业 / 家庭结构
```

这一层**几乎不产生洞察**。它的作用是**排除**——如果对方只给得出这一层，说明还没开始做洞察。

### 层 2：情境（在什么场景下消费内容）

```
什么时候刷手机？    通勤 / 睡前 / 摸鱼 / 厕所
用什么设备？        手机为主
看多久？            15 秒 / 3 分钟 / 10 分钟
在哪里看？          地铁上（不能开声音）
```

**情境决定形式。** 地铁上不能开声音 → 字幕必须可读。

### 层 3：张力（真正的洞察所在）

**张力 = 想要 A，但被 B 挡住。**

常见的六种张力结构：

| 张力 | 结构 | 例 |
|---|---|---|
| **身份冲突** | 我应该是 X，但我感觉自己是 Y | 应该是成熟大人，但内心还是小孩 |
| **时间冲突** | 我想要 X，但来不及了 | 想转行，但已经 35 岁 |
| **价值冲突** | 我知道该 X，但我做不到 | 知道该早睡，但停不下来刷手机 |
| **关系冲突** | 我想要 X，但那意味着背叛 Y | 想离开小城市，但父母在 |
| **资源冲突** | 我想要 X，但我没有 Y | 想创业，但没本金 |
| **意义冲突** | 我得到了 X，但没意义 | 加薪了，但更空虚 |

### 层 4：未被满足的需求

```
读者想要什么表达？（他想说什么但说不出口）
读者想要什么身份？（他想被看成什么人）
读者想要什么确认？（他想确认自己是对的）
```

**这一层直接对应内容的「转发理由」。**

---

## 第二步：从数据反推洞察

如果有内容数据，用这些指标反推：

| 现象 | 可能洞察 |
|---|---|
| 阅读高、转发低 | 内容满足好奇，但不代表读者立场 |
| 阅读低、转发高 | 内容小众但精准击中某群人 |
| 收藏高、阅读低 | 工具价值高，但传播性弱 |
| 评论多、转发少 | 有争议，但读者不愿公开站队 |
| 完读低 | 开头留不住，或形式不适配情境 |

**没有数据怎么办？** 用「自我代入法」：把自己放进目标读者的一天，写出**他会在哪一刻想起这个问题**。

---

## 第三步：输出洞察简报

```markdown
# 洞察简报：{主题}

## 读者
- 人口：{年龄/城市/职业/收入}
- 情境：{什么时候看/看多久/什么设备}

## 核心张力
{想要 A，但被 B 挡住}

## 未被满足的需求
- 想表达的：{...}
- 想成为的：{...}
- 想确认的：{...}

## 内容启示
- 应该写：{...}
- 不该写：{...}
- 转发理由：{...}

## 验证方式
{怎么知道这个洞察对不对}
```

---

## 第四步：洞察质量自检（5 项）

- [ ] 这个洞察**不能**只靠人口统计得出？
- [ ] 它解释了**为什么**，不只是**是什么**？
- [ ] 它能让读者产生「这说的就是我」的反应？
- [ ] 它同时包含**想要**和**阻碍**？
- [ ] 换成同类人群，它还成立吗？（成立说明太泛，不成立说明够具体）

## 参考框架【外部方法论，非本引擎实测】

| 框架 | 出处 | 用途 |
|---|---|---|
| **Jobs to Be Done** | Clayton Christensen | 读者「雇佣」内容来完成什么任务 |
| **Account Planning** | Stanley Pollitt / BMP | 把消费者研究带入创意决策 |
| **受众分层** | 新闻编辑室实践 | 核心受众 / 泛受众 / 偶然触达 |
| **文化张力** | 广告业常用 | 社会共识与个体欲望的冲突 |

**用法**：这些是**外部框架**，作用是**提供提问角度**，不是提供答案。
标注时必须写【外部】；本引擎自己的实测数据另标【实测】。

---

## 边界

不做：用户调研执行（需要真实访谈）、数据采集（需要工具权限）、流量预测（无法验证）。

**如果用户只给得出人口统计，直接说**：「这一层不足以做洞察，需要知道他们在什么场景下、卡在哪里。」
