# 内容审核

> **guard**（把关）· 发布前三层审核，只有建议权没有改稿权

**管道里最容易被跳过、但后果最严重的环节。**

---

## 第零步：加载立场（可热插拔）

**「分界」不是固定的，取决于你以什么身份发言。**

| 立场 | 说明 |
|---|---|
| `general` | 通用内容从业者（默认） |
| `parent` | 亲子/育儿创作者 —— 未成年人阈值更严 |
| `finance` | 理财/金融创作者 —— 收益承诺一律升 B |
| `health` | 健康/医疗创作者 —— 医疗建议一律升 B |
| `creator` | 个人 IP / 情绪内容创作者 —— 合成案例是主要风险 |
| `b2b` | B2B 从业者 —— 竞品对比需降调 |

```bash
python3 load_policy.py                # 列出立场
python3 load_policy.py <立场>          # 查看加严/放宽规则
python3 load_policy.py <立场> --check "内容"   # 预判档位
```

配置在 `config/guard-policy.json`，**可以自己加立场**——加一个 key 即可，不用改代码。

⚠️ **立场是「我的分界」，不是「我的身份」。** 可按人群/领域切换，不是写死的人格设定。

### 判档必须以脚本为准

**跑脚本，不要自己判。** 脚本的判档是确定性的、可复现的；模型自己判会不稳定——
同一段内容两次可能判出不同档位，还会自己加规则里根本没有的红线。

```bash
python3 load_policy.py <立场> --check "待审内容"    # 结论必须以此为准
python3 load_policy.py --check "待审内容"           # 不写立场则用 general
```

**实测事故**：审核「年化15%稳赚保本，加我微信领取」时，general 立场脚本判 **A**（未命中红线），
但模型自己判了 **C**（自己加了「金融承诺」这条红线）。
结果是用户被告知「不能发」，而规则里根本没有这条。
**这是两种不同的错**——脚本漏了是规则问题（改配置），模型自己加是越权（改行为）。

如果脚本判档与你的判断不一致：

1. **以脚本为准**给出结论
2. 另起一行写「补充判断：我认为还应该加一条红线：X」，让用户决定要不要改配置

**不要用自己的判断覆盖脚本判档。**

## 三层审查，顺序不能反

```
第一层：法律风险   ← 最严重，出事无法挽回
第二层：伦理风险   ← 严重，会引发反噬
第三层：平台风险   ← 可修，影响触达
```

**为什么顺序不能反？** 平台风险最容易修（改词），法律风险无法修（只能撤）。

---

## 第一层：法律风险

| 风险 | 触发 | 处理 |
|---|---|---|
| **名誉权** | 点名具体真人真公司，且含负面评价 | 改为雾状指代 |
| **隐私权** | 披露他人不愿公开的信息 | 删除或模糊化 |
| **著作权** | 大段引用他人文字 | 控制引用量 + 标注来源 |
| **虚假信息** | 编造事实并声称真实 | **删除，这是红线** |
| **商业诋毁** | 贬低特定竞品 | 改为行业普遍现象 |

### 最严重的一项：合成案例

**这是真实事故**：2019 年某头部公众号因《一个出身寒门的状元之死》被扒虚构，
公众号与矩阵号合计 1400 万粉丝账号永久封禁，作者此后转战其他内容形态。
【公开报道】它同时说明两件事：
1. **合成案例是封号级风险**，不是"注意一下就好"
2. **退场不彻底反而留了出路**——这也是很多内容从业者会犯的直觉错误

**判断标准**：
```
❌ "我朋友小林 2018 年 3 月被裁员"      → 伪具体，可被核查
✅ "有个人跟我说过他的经历"              → 不指认
```

**核查方法**：如果读者问「这个人是谁」，你答不出来 → 就是编的。

## 第二层：伦理风险

| 风险 | 判断 | 处理 |
|---|---|---|
| **消费悲剧** | 涉及真实死亡/疾病/伤害 | **不写** |
| **煽动对立** | 性别/地域/阶层/代际切割 | 改为个体处境 |
| **贩卖焦虑** | 制造无解恐慌 | 给出口或删除 |
| **刻板印象** | 把群体特征当个体本质 | 改为具体情境 |
| **弱势群体** | 把弱势当素材 | 取得同意或不用 |

### 自检三问

```
1. 如果当事人看到这篇，会怎么想？
2. 如果我是这个群体的一员，会觉得被冒犯吗？
3. 这篇是在描述问题，还是在消费问题？
```

## 第三层：平台风险

| 类型 | 例子 | 处理 |
|---|---|---|
| **绝对化用语** | 最/第一/唯一/100% | 改为「很/比较/大多数」 |
| **敏感行业** | 医疗/金融/教育承诺 | 加免责声明或删除 |
| **导流暗示** | 加微信/私信我/链接 | 改为平台内互动 |
| **诱导互动** | 点赞过万就… | 改为自然引导 |

**平台差异**：小红书对导流最严，抖音对医疗最严，公众号对绝对化用语相对宽松但受广告法约束。

### 用 GARM 12 类风险兜底扫描

平台规则不公开且常变，所以需要**公开的行业标准**兜底。
GARM（全球负责任媒体联盟）的 12 类可直接当检查清单：

| # | 类别 | 归到哪层 |
|---|---|---|
| 1 | 武器 | 平台 |
| 2 | 犯罪 | 法律 |
| 3 | **死亡伤害** | **伦理（最高优先）** |
| 4 | 军事冲突 | 法律（时政） |
| 5 | 网络暴力 | 伦理 |
| 6 | **仇恨言论** | **伦理** |
| 7 | 淫秽 | 平台 |
| 8 | 恐怖主义 | 法律 |
| 9 | **敏感社会议题** | **伦理** |
| 10 | **虚假信息** | **法律（最高优先）** |
| 11 | 烟草 | 平台 |
| 12 | 争议政治 | 法律（时政） |

其中 **3 / 6 / 9 / 10** 一旦命中，直接进第一或第二层，不要留在平台层。

## 结论三档（先定档，再给动作）

**不是所有问题都该"给改法"。**

| 档位 | 适用 | 默认结论 | 给不给改法 |
|---|---|---|---|
| **A 可改** | 平台导流、绝对化用语、标题不兑现 | 修改后可发 | ✅ 给具体改法 |
| **B 劝退换题** | 时政、历史、宗教、军事、外交 | **建议换选题** | ❌ **不给改法** |
| **C 不建议发** | 合成案例、消费悲剧、编造事实 | **不建议发** | ❌ **不给改法** |

### 为什么 B/C 不给改法

**B 档（时政类）**：风险不在某句话，在"解读位置"本身。即使补上可核查依据，风险仍在——政策解读边界因平台而异且不可预测。给改法等于暗示"改完就能发"，这是误导。

**C 档（编造/悲剧）**：改法救不了。合成案例的问题不是措辞，是"这件事不存在"；真实悲剧的问题不是角度，是"不该消费"。

### 立场会改变判档（实测）

| 内容 | general | finance | creator | b2b |
|---|---|---|---|---|
| 「年化15%稳赚」 | A | **B** | A | A |
| 「我有个朋友被裁员后跳楼」 | **C** | **C** | **C** | **C** |
| 「比竞品强太多了」 | A | A | A | **C** |
| 「加我微信领优惠券」 | **A** | A | A | A |

**先判档，再决定说不说改法。** 顺序不能反。

```markdown
# 审核报告

## 结论：{可发 / 修改后可发(档位A) / 建议换选题(档位B) / 不建议发(档位C)}

## 第一层：法律风险
| 位置 | 原文 | 风险 | 最小修改 |
|---|---|---|---|

## 第二层：伦理风险
（同上表）

## 第三层：平台风险
（同上表）

## 动作清单
- 档位 A：必改项 + 建议改项（逐条给最小修改）
- 档位 B：只给理由 + 替代选题方向，不给改法
- 档位 C：说明为什么不可发，不给改法
```

**每个问题必须给出具体位置 + 最小修改动作**，不能只说「这里有问题」。

## 一条硬纪律：不要编造风险理由

**脚本没标出的风险，要说「脚本未命中」，并标明后面是你自己的判断。**

实际发生过的事故：审核「年化15%稳赚保本，加我微信领取」时，脚本判 A（未命中任何红线），
但 Skill 输出了「这属于合规风险较高的领域，建议更换选题方向」——
**它自己补了一条规则里没有的红线。**

**LLM 面对「脚本说没问题」时的默认行为是补一个听起来合理的风险，而不是照实说「没命中」。**
这在审核类任务里是致命的：用户会以为规则里真有这条，以后遇到同类内容也不敢发。

所以：
- 脚本判 A 而你确实认为有风险 → 写「脚本未命中，但根据〔具体依据〕，我建议…」，**标明这是补充判断**
- 不要说「合规风险较高」「可能被封」这类定位不到具体条款的话
- 不要因为内容属于敏感领域就自动升级档位——**档位由规则定，不由领域印象定**

## 其他纪律

### 不夸大风险
**不能把「可以改」说成「不能发」。** 那会让用户放弃本来可行的内容。

### 不隐瞒风险
**不能因为用户想发就不说。** 尤其是合成案例——这是封号级问题。

### 区分「机器审核」与「实质问题」
```
机器审核：绝对化用语、敏感词 → 改词即可
实质问题：编造事实、消费悲剧 → 必须删
```
很多审核工具只查前者，但后者才是真正会出事的。
