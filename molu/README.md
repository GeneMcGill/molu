# 墨炉 molu



一条从**洞察到复盘**的完整内容生产管道。**装 1 个包，用 11 个模块。**

```
  墨炉 molu —— 从洞察到复盘的内容生产引擎

  ░ 原料层 ░  Corpus Source（可插拔换源，引擎零改动）
     写作方法论(4A·咨询框架) · 素材库(16,227 单元) · 实时热榜
                ↓
         kb.py · 统一数据层
                ↓
  ░ 主管道 ░  Pipeline（①→⑤ 顺序执行，不可跳步）
     ① 洞察 insight  →  ② 策略 strategy  →  ③ 雷达 radar
     → ④ 选题 topic/reuse  →  ⑤ 生产 writer/video
                ↓
  ░ 收束层 ░
     ⑥ 审核 guard  →  ⑦ 拆解 teardown  ⇄ 反馈回 ①
     ⑧ lens ◈ 视角 —— 贯穿全程
```

---

## 三条命令

```bash
# 1. 安装
npx skills add <repo>
# 或
cp -r molu ~/.agents/skills/molu

# 2. 用（直接说话；面板按名称字典序排，管道位置在各模块 description 开头的 ①→⑪）
/molu-console  这套东西能干嘛
/molu-writer   帮我写一篇
/molu-guard    这篇能发吗

# 3. 换语料（一条命令，模块零改动）
python3 kb.py install <语料源ID>
```

## 模块对照表

排序依据：本表按主管道 flow 顺序排（安装脚本也按此顺序创建模块）；面板内由 agent 按名称字典序展示，位置在各模块 description 开头的 ①→⑪ 标注。

| 英文名 | 中文 | 一句话 |
|---|---|---|
| `console` | 总控台 | 显示管道图、判断你在哪一环、调度其他模块 |
| `insight` | 洞察 | 读者是谁、卡在哪、未被满足的需求 |
| `strategy` | 策略 | 定位、人群、节奏、形式 |
| `radar` | 雷达 | 抓实时热点，过滤红线，转成可写选题 |
| `topic` | 选题 | 输入领域，产出 20 个带依据的选题 |
| `reuse` | 复用 | 把一个主题榨出 10 个不同角度 |
| `writer` | 写稿 | 长文/图文，按平台规格产出可发布稿 |
| `video` | 短视频 | 口播脚本、分镜、字幕切分 |
| `guard` | 把关 | 发布前三层审核，只有建议权没有改稿权 |
| `10-teardown` | 拆解 | 用 12 指标拆解为什么爆/为什么不爆 |
| `11-lens` | 视角 | 用内容从业者的判断标准审视写作决策 |

每个模块的 `SKILL.md` 里有 `metadata.aliases`（含中文名），
英文名是主名（命令用英文），中文辅助理解。

```bash
npx skills add <repo>
# 或
cp -r molu ~/.agents/skills/molu
```

## 数据层：kb.py

模块不各自带数据副本，**统一通过 `kb.py` 查询当前语料源**。

```bash
python3 kb.py stats                        # 数据概览
python3 kb.py get GLD 10                   # 取 10 条高复用金句
python3 kb.py search TGT 稳定 5            # 靶子中搜索
python3 kb.py find 存钱 10                 # 跨类型检索
python3 kb.py topics                       # 主题分布
python3 kb.py inlets                       # 语料源列表
python3 kb.py install <name>               # 切换语料源（自动校验）
```

**路径无关**：`kb.py` 用 `__file__` 定位引擎根，从任何 cwd 都能跑。

**这就是「换语料模块零改动」的实现方式**：模块只写查询命令，不写数据路径。

## 语料源（Inlets）

**语料是语料源，不是地基。**

依据是本项目自己的实测：写法层四年不变（段落中位 21 字、金句中位 19 字、单篇 18 单元），
变的是话题层。所以**换语料换的是输入，管道不需要改**。

### 每个语料源必须提供四份声明

| 文件 | 作用 | 缺了会怎样 |
|---|---|---|
| `manifest.json` | 元信息（id/版本/规模/时间范围） | 无法识别 |
| `vocabulary.json` | **分类词表（冻结）** | **口径漂移，拒绝接入** |
| `stats.json` | 分布特征 | 诊断会用错基线 |
| `provenance.json` | 溯源与合规 | 无法控制分发 |

```bash
python3 scripts/inlet_check.py inlets/<你的id>
```

**任一项不满足 → 拒绝接入。** 宁可只有一个语料源，不要五个口径不一致的。

## 审核立场（可热插拔）

**「分界」不是固定的，取决于你以什么身份发言。**

```bash
python3 guard/load_policy.py              # 列出立场
python3 guard/load_policy.py finance       # 查看该立场规则
python3 guard/load_policy.py finance --check "年化15%稳赚"
```

内置立场：`general` / `parent` / `finance` / `health` / `creator` / `b2b`

**实测：立场会改变判档**

| 内容 | general | finance | creator | b2b |
|---|---|---|---|---|
| 「年化15%稳赚」 | A | **B** | A | A |
| 「我有个朋友被裁员后跳楼」 | **C** | **C** | **C** | **C** |
| 「比竞品强太多了」 | A | A | A | **C** |

加新立场只需在 `guard/config/guard-policy.json` 加一个 key，**不用改代码**。

---

## 审核三档

```
A 可改      → 修改后可发，给具体改法
B 劝退换题 → 建议换选题，不给改法
C 不建议发  → 说明为什么不可发，不给改法
```

## 一条原则：深优先于快

> **如果你走得快，先走深。**

| 场景 | 快的做法 | 深的做法 |
|---|---|---|
| 拿到热点 | 立刻套模板写 | 先问背后的**永恒痛点** |
| 出选题 | 一次给 20 个 | 先确认**写给谁** |
| 写稿 | 一次产出成品 | 先对齐**心理位置** |
| 要发布 | 写完就发 | 过 `guard`，它有权说「别发」 |

**深度不是拖延。** 判断标准：

```
这个问题再想一轮，会改变结论吗？
  会   → 慢下来，值得
  不会 → 现在就做，别耗
```

## 使用纪律

1. **不跳过审核** —— 要发布的内容必须过 `guard`
2. **不编造案例** —— 硬红线（2019 年某头部账号因合成案例永久封禁）
3. **不承诺流量** —— 不做流量预测，归因需真实后台数据
4. **区分实测与外部** —— 每条结论标注来源
